# CJK glyphs

`cjk32.bin` holds the bitmap glyphs yaft uses for Japanese text: wide 32x32
glyphs (two terminal cells) for kana, kanji, CJK symbols and full width forms,
and 16x32 glyphs for half width katakana. It is generated by
`gen_cjk_glyphs.py` (python3 + Pillow) from
[BIZ UDGothic Regular](https://github.com/googlefonts/morisawa-biz-ud-gothic),
licensed under the SIL Open Font License 1.1 (see `OFL.txt`).

* Font: `ofl/bizudgothic/BIZUDGothic-Regular.ttf` of
  [google/fonts](https://github.com/google/fonts) at commit
  `01ac47e0b1cddbc298334c69a5dfafb0205ffa28`, checked against SHA256
  `709fcd41e3209fb765da750472f55ccdf925653e9fa7e1eb007cb65c8f749c75`.
* Output: SHA256 `c7f60ef01f62099652966550ed2c78c0f530c89687d5f4bc1523250a4edc03b8`
  when generated with the container of `shingetsu/docker/host.Dockerfile`
  (Pillow's FreeType may rasterize slightly differently elsewhere).
* Rendering: 30px em, baseline on row 26 like the builtin Latin glyphs,
  anti-aliased coverage thresholded at 110/255.
* Only characters a terminal shows as two cells (East Asian Wide/Fullwidth)
  get a wide glyph, since a mismatching width makes yaft fall back to `?`.

Regenerate with
`shingetsu/scripts/host-test.sh run python3 shingetsu/fonts/gen_cjk_glyphs.py`.

## Format

Little endian: `"YGL1"`, `u32` count, then count records sorted by codepoint,
each 136 bytes (the size of `glyph_t` in `apps/yaft/glyph.h`):
`u32 code, u8 width (1|2), 3 pad bytes, u32 bitmap[32]`. A row's word has the
leftmost pixel in the most significant bit of its cell width (bit 31 for width
2, bit 15 for width 1).

The file is embedded into the binary (`CMakeLists.txt`, like `vendor/noto`)
and loaded by `apps/yaft/terminal_adapter.cpp`; the builtin glyphs keep
priority.
